# Findings, 2026-10-04

Rows appended by the agents that built the lab and the SWE hive.

## SWE lab build (`examples/lab/src/swe`): friction in core, driver and speech

Found while building the SWE hive, its single-agent baseline and the Harbor
wrapper. Each row is a friction, a bug or an improvement idea, with the place
it bit.

| Area | Finding | Impact | Suggestion |
| --- | --- | --- | --- |
| speech `tool_specs` | The five tools the hive offers (`post`, `broadcast`, `ask`, `complete_episode`, `read`) carry long descriptions that a host must render verbatim and resend on every model call. | A fixed per-call token cost on the arm being measured; it is paid per call, not per turn, so it grows with the number of seats and rounds. | Ship a compact description variant or a documented token estimate per spec, and a test that bounds total description size. |
| speech `interpret` | `interpret` accepts any served tool name, including `dm` and `ask_teammates`, even when the host did not offer them to the model. The host has to filter by offered names itself. | Easy to forget; a model that hallucinates an unoffered tool gets it accepted. | `interpret_among(name, args, allowed)` or an `allowed` field on the call arguments. |
| speech text rule | "Text outside a tool call reaches nobody." gpt-oss-class models often end a turn with plain text. | The lab promotes final text to an implicit `post`; without that a seat's whole turn vanishes. | Make the implicit-post policy a documented, core-owned option (`ImplicitPost::{Never, FinalText}`) so hosts agree. |
| speech `commit_utterance` | Needs `Roster`, `DeskSet`, `DispatchConversation` and `AsidePolicy` on every call, and `Roster`/`DeskSet` are borrowed views over slices the host must own. | The lab needs a `World` owner struct and a per-call rebuild just to append one row. | A `Desk`-level owned handle with `commit(speaker, utterance)`, built once. |
| speech `ask` | An `ask` opens an obligation the host must track until it is answered. No pure fold reports open asks per seat. | The lab did not offer `ask`-gated completion; a host that does would reimplement the bookkeeping. | A fold `open_asks(&rows) -> Vec<(asker, target)>` next to `pins`. |
| speech `broadcast` | Routing is "one TypeSafe Choice over the eligible team", which is a model call per broadcast. | An extra model call (tokens, latency) on the hive arm that the single arm never pays; hard to account for fairly. | A deterministic router fallback (role keywords or a response-threshold score) so the cost of semantic routing can be switched on and measured separately. The lab uses a keyword router (`hive::route_broadcast`). |
| `hive::step` | The deliberation fold is built on topics, bids and quorum. An open-ended task (fix a bug in a repo) has no topics, so the lab wrote its own mention-driven queue and used `hive::step` for nothing. | The "scheduled by core" claim does not hold for work-style rooms. | A pure `plan_round(queue, width)` plus "wake on mention, lead on quiet" policy in `driver`, so work-style rooms share the width bound by construction. |
| telemetry `TraceEvent` | `Round` and `Converged` require deliberation types (`Phase`, `Visibility`, `BidReason`, `TopicId`). The lab emits `Phase::Deliberate`, `Visibility::Full` and `TopicId("task")`. | The viewer shows deliberation labels for a coding run; the types lie slightly. | A host-neutral `Round { seats, label }`, or documented conventions for work rooms. |
| telemetry `TurnFinished` | Only `input_tokens` and `output_tokens`. gpt-oss reasoning tokens are folded into completion tokens and cached prompt tokens are invisible. | Cannot tell reasoning spend from answer spend, or see prompt-cache savings, which is exactly what a context-trimming intervention changes. | Optional `reasoning_tokens` and `cached_tokens` fields. |
| `Digester` port | The port assumes a model. A model fold adds tokens to the arm being measured. | The lab ships a zero-token extractive digester (`board/digester.rs`); a fair comparison needs one, and every host will write the same thing. | Ship an extractive `Digester` in core (pure, no model) and name it as the cost-neutral default. |
| `refold` / `read_pinboard` | They return futures although the lab's log and digester resolve immediately; the lab needs its own `block_on`. | Sync hosts carry an executor shim; the lab's `exec.rs` exists only for this. | Sync twins for ports that are ready, or a `block_on` in core behind a feature. |
| `SessionLog` | Core ships the port and no in-memory implementation, so every host and test rewrites `MemoryLog`. | Duplicate code; subtle ordering and cursor bugs recur. | A `testing` module with a reference in-memory log. |
| digest `ChannelHead` | `unfolded_chars` must be computed by the host, so the lab rescans every row on each `maintain`. | O(rows) per call; fine here, wrong for a long desk. | Have `ChannelDigest` carry the running char count of the rows it covers, or accept an iterator. |
| pins | `!pin` excerpts are 120 characters. A failing test name plus its command rarely fits, so the lead's pinned facts are clipped. | The pin is meant to carry the one fact nobody may lose. | Make `PIN_EXCERPT_CHARS` a `fold_pins` parameter, or show a short message whole. |
| concurrency | Seats share one container and one transcript lock, but nothing in core models a claim on a resource (a file). Implementer and tester can edit or run against the same files in the same round. | Round width bounds turns, not conflicts; wider rounds raise the chance of racing edits. | A stigmergy-style claim marker (`!claim path`) and a fold that reports contested paths, so a round can avoid scheduling two seats on the same one. |
| Harbor wrapper | The installed Harbor has no `--agent-import-path` flag; a custom agent is passed as `--agent module:Class` with the module on `PYTHONPATH`. | Older instructions for Harbor fail on this version. | Documented in `examples/lab/harbor/README.md`. |
| context cost | A hive seat restarts from a briefing every activation, so it loses its own bash history and re-reads files the previous activation had open. | Trims the repeated context but can cost extra tool calls; whether it nets out is the experiment. | Let a seat pin a short "working notes" row for itself (viewer-limited), measured as its own arm. |

## Knob lab (`examples/lab`: memory_hive, context_tools, swarm_knobs, driver_knobs, relay_hive, gate_knobs)

Scripted, offline, deterministic runs that drive every public knob of
`tinyhivemind-core` and print what happened. Each row is something that was
hard, surprising, missing or wrong while doing that. The columns are:

- **row**: `F1`, `F2` ... the number the lab README's coverage matrix cites.
- **observation**: what was seen.
- **evidence**: the binary and section whose output shows it (run it with
  `cargo run --manifest-path examples/lab/Cargo.toml --bin <name>`), or the
  source line when the finding comes from reading code.
- **proposed improvement**: the change, tagged with the axis it moves:
  `concurrency`, `tokens`, `intelligence` or `API ergonomics`.
- **disposition**: `open` (needs a decision), `open: bug` (behaviour looks
  wrong; no crate change made, see the note), `docs` (text to fix), `by
  design` (recorded so nobody rediscovers it), or `dup` (also raised in the
  SWE lab table above).

A row marked `open: bug` was not fixed here: the lab does not modify `crates/`
unless a defect blocks it, and none did. Each has a repro in the lab output, so
the failing test the contract asks for can be written straight from it.

### Memory: digest, pins, sharing, briefing, elsewhere, threads

| Row | Observation | Evidence | Proposed improvement | Disposition |
| --- | --- | --- | --- | --- |
| F1 | Core ships `SessionLog`, `Digester` and a boxed-future port style but no in-memory log, no digester and no executor. The lab wrote all three (`log.rs`, `exec.rs`, a scripted `Digester`); ten test modules in core carry their own `FakeLog`. | `memory_hive` throughout; `grep "impl SessionLog for" crates/tinyhivemind-core/src` | API ergonomics: a `testing` feature with one reference `MemoryLog` and a `block_on`; an extractive `Digester` as the zero-token default. | dup (SWE rows: `SessionLog`, `refold`, `Digester`) |
| F2 | A seat cannot reach the digest. `initialize_session*` take no digest, so the lab had to smuggle the account in as a `BriefingNote`; the `read` tool returns only recent rows; `BrevityPolicy::rule_text` tells seats to "pin or search" but `tool_specs()` has no search tool. | `memory_hive` digest + briefing (the "Earlier in this channel" note); `context_tools` tool table (7 tools, none search) | intelligence: `initialize_session_with_digest(…, account)` that applies it; a `search`/`recall` tool spec or reword the rule. | open |
| F3 | `project_session` can only page backwards from `before`, never forwards from an `after`. With `keep_live: 10` and the default window of 30, a seat is projected 30 rows and `apply_digest` then discards 20 of them. | `memory_hive` "apply_digest narrows a projected window": 30 rows -> 10 | tokens: `SessionQuery.after: Option<Sequence>` so the read starts at the account's `through`, or have `apply_digest` ask for the window to be topped up. | open |
| F4 | A first fold over a long history is a serial chain: 70 rows at `input_limit: 20` took three digester calls, each carrying the previous account as `prior`. | `memory_hive` "refold ... to a fixed point": steps 1-3, `prior=true` from step 2 | concurrency: plan disjoint ranges that can be summarized in parallel and merged by one last call; or document that the chain length is `ceil(rows / input_limit)`. | open |
| F5 | `Digester` is only a trait. Nothing tells the model what to do with `DigestRequest.pinned`, the budget or the prior account, so every host writes its own prompt and the contract ("keep what the pins say") lives only in a doc comment. | `memory_hive` Scripted digester has to read `request.pinned` by hand | intelligence: `digest_instructions(&DigestRequest) -> String`, the default prompt, tested against `accept_digest`. | open |
| F6 | The pinned row's excerpt includes the `!pin` marker and the note repeats the rest of the line, so a self-pin spends its text twice in the briefing: `[9] #self "!pin #self a long opening ..." — a long opening ...`. | `memory_hive` pins: `pin_note` output; also `briefing` context text | tokens: strip marker lines from the excerpt, and drop `note` when it is the excerpt's tail. | open |
| F7 | The thread index treats every top-level row as a thread, so a desk with no threads shows its last five messages, including pin markers, as `no replies`. They duplicate the history window. | `memory_hive` briefing context: `[8] "Noted." — no replies`, `[3] "!pin #retry …"` | tokens / intelligence: skip zero-reply roots, or take a `min_replies` argument. | open |
| F8 | `window` counts raw rows before narrowing, so a viewer can get far fewer messages than asked: window 2 returned one row, because a reply whose root fell outside the window is dropped. `stated_window` then tells the seat the smaller number ("shows about 5 messages" after a request for 10), which conflates asked with shown. | `context_tools` projection "window 2 for carol: ^6"; `memory_hive` `initialize_session: 5 history rows, stated window 5` | intelligence: say whether `window` bounds raw rows or returned messages and keep the briefing's number honest. | docs |
| F9 | `gather_elsewhere` skips the current conversation by comparing raw `desk_id`, so `main` and `General` (one desk by `Conversation::equivalent_to`) are both returned. It also never checks that the seat sits on a listed desk, and `render_row` returns `None` for an aside stub, so an elsewhere reader loses the signal that something private happened. | `memory_hive` elsewhere: "gather_elsewhere with current=main and listed=general returns 1 conversation(s) (0 expected …)"; "dave … is handed 1 row(s) of eng" | API ergonomics: use `equivalent_to`; document that membership is the caller's check; render stubs. | fixed: alias skip now uses `Conversation::equivalent_to`; membership stays the caller's check and aside stubs are still open |
| F10 | `Desk.description` never reaches a seat. `TeamBriefing::from_snapshots` always yields `role: None, description: None`, so teammates read as `@bob — Bob` and the desk's purpose appears only in `RoutingRequest.desk_purpose`. | `memory_hive` briefing text; `crates/.../runtime/briefing/mod.rs` comment "Snapshot records have no role or description fields" | intelligence: render the desk purpose and let `RosterMember` carry a role. | open |
| F11 | `ChannelHead.unfolded_chars` is host-computed and `fold_after_chars` defaults to 400,000, so by default the size trigger never fires. | `memory_hive` digest: size trigger needs `fold_after_chars: 400` to bite at head ^16 | tokens: a helper that counts desk-visible characters above an account; a lower default. | dup (SWE row `ChannelHead`) |
| F12 | `runtime::Error::Read`'s `Display` is "session log read failed"; the host's cause is only on `source()`. | `memory_hive` contract: `session log read failed (source: the journal is unreachable)` needs a source walk | API ergonomics: include the cause in `Display` or ship a chain-printing helper. | open (low) |

### Swarm: episode, quorum, attention, directory, exchange

| Row | Observation | Evidence | Proposed improvement | Disposition |
| --- | --- | --- | --- | --- |
| F15 | `Basis::Sequence` (the default) counts private rows against the quorum window. With three private rows per turn and `window = 9`, the same room exhausts its budget at 12 turns; `Basis::Live` converges in 7. | `swarm_knobs` sweep, group `distance` | intelligence: default to `Basis::Live`, or warn when an episode has private rows. | open |
| F16 | `HiveStep::Speak` says a seat is in `Phase::Commit` but not which topic won, so the seat refolds the traces itself and must reproduce `step`'s rows, horizon and basis exactly. The lab's first version used the wrong horizon under `Basis::Live`, never saw the quorum, and exhausted. | `swarm_knobs/room.rs` `says`; sweep group `distance` before the fix | API ergonomics: carry `ConsensusState` and standings on `Speak`, or `HiveTurn::context`. | open |
| F17 | `QuorumPolicy.require_grounded` exempts `Propose`: two ungrounded proposals carry quorum on their own. Only supports and objections are gated. | `swarm_knobs` sweep `quorum.require_grounded`: both settings converge with seats that cite nothing; `hive/quorum/mod.rs` line `trace.kind == TraceKind::Support && !trace.grounded()` | intelligence: gate proposals too, or document it as the policy. | open |
| F18 | Width changes the decision, not just the clock. The same five scripted seats converge on `#x` at `round_width` 1 and 2 and on `#y` at 4 and 5. The cause was not isolated: a wide blind round authorizes the first four bidders together, so who has spoken when the room turns revealed differs. | `swarm_knobs` sweep group `round_width` | concurrency / intelligence: report which seats were unheard when a round was authorized; check with a model that the order effect is real and not a script artifact. | open |
| F19 | `blind_round: false` converges in three turns on two seats that echo each other. | `swarm_knobs` sweep group `blind_round` | tokens vs intelligence: record the trade in the policy docs. | by design |
| F20 | With evaluations, support is the sum of `probability * evidence_quality`, so `threshold: 2` needs three supporters at 0.95; two supporters at 0.95 give 1.90 and do not carry. A missing evaluation counts for nothing; a stale one aborts the whole fold. Nothing in the library produces a `DecisionEvaluation`; only `examples/bench/jev.rs` does. | `swarm_knobs` consensus "quorum by evaluation" | intelligence: scale the threshold or state the units; drop stale evaluations instead of failing; ship the producer in `typesafe`. | open |
| F21 | The attention constants (`SPEAK_COST` 500, addressed 2000, dissent 1500, quiet 1000, dominance penalty 3000) and the directory's deposits are hard-coded, not policy fields. `dominance_cap`, `repetition_cap` and the weights do not move a five-seat outcome unless thresholds are skewed. | `swarm_knobs` sweep groups `dominance_cap`, `repetition_cap`, `weights` (identical rows) vs the `(eli eager)` groups; `bids` table | intelligence: make them `AttentionPolicy` fields so they can be swept. | open |

### Driver and routing

| Row | Observation | Evidence | Proposed improvement | Disposition |
| --- | --- | --- | --- | --- |
| F22 | A broadcast whose only recipient has a full queue is dropped, and the author's work is closed anyway. `place()` removes `ran_for[author]` so the author is owed a turn, but `fold_broadcast` then completes the author's assignment. | F23 | Every committed broadcast pays a router call, even with one eligible candidate. | `driver_knobs` raw "a two-seat episode, one eligible candidate: ... router asked 1 time(s)" | tokens: skip the model when at most one candidate is eligible. | open |

| F28 | The nudge note tells a seat that is waiting on its own ask to "finish your part ... or ask one of them a question", though it cannot complete. | `driver_knobs` sweep: `nudgedx2` in the chatty-tester rows; `driver/conduct/mod.rs` `begin_wave` | tokens: skip seats with outstanding asks, or give them a waiting note. | open |

| Row | Observation | Evidence | Proposed improvement | Disposition |
| --- | --- | --- | --- | --- |
